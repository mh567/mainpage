# emolu.cn 作品官网模板设计

## 目标

让从搜索、GitHub 或个人主页进入的访客，在首屏看懂作品能做什么、适用于什么平台，并找到演示、下载或安装入口。每个作品可通过 `https://emolu.cn/<slug>/` 单独分享，其官网与其他作品一起由当前 Astro 站点构建和发布。

## 页面结构

| 位置 | 内容 | 呈现方式 |
| --- | --- | --- |
| 顶部 | 作品名称或图标，实际存在的章节，返回个人主页 | 导航按该作品的内容生成，手机端保留必要入口 |
| 首屏 | 作品名、具体用途、平台、主操作、产品截图 | 桌面端左文右图。手机端先给操作入口，再展示图片。多平台作品可同时展示平台入口。截图按原始比例呈现，缺图时采用完整的单栏首屏 |
| 用法与能力 | 通过两至三个具体场景解释作品的用途，可配图 | 按作品内容展开，允许一项能力使用一张大图，少量内容可直接用短段落说明 |
| 获取与安装 | 下载变体、前置条件、安装或演示说明 | 软件下载可列多个架构。在线应用引导进入演示。源码项目提供快速开始及完整文档 |
| 页尾 | GitHub、版本发布、问题反馈、返回个人主页 | 只显示已配置的链接 |

共用版式、字号层级、留白和交互。各作品用自己的主色、图标和真实截图建立识别度，主色用于按钮、链接和截图底板。多平台作品共用产品视觉，每个平台的截图标明适用版本。长截图和桌面应用的横向截图可用不同的展示比例，手机端保持截图与文字可读。预览图配描述性替代文本，按钮和链接有可见的键盘焦点。

Peek 的平台下载选择适合 AriaPilot。[Peek 官网](https://peek.yuntianyou.cc/) PDF Craft 将入口放在首屏并用真实结果解释用途，适合借鉴到 habu 和 InkBuddy。[PDF Craft 官网](https://pdfcraft.ai/zh-CN/)

## 首批三个作品

| 计划路径 | 首屏拟文案 | 主操作 | 优先准备的截图 |
| --- | --- | --- | --- |
| `/habu/` | 把常用工具集中到一个个人工作台 | 在线体验，链接到现有 Demo | 工作台全貌，配一个真实使用场景 |
| `/ariapilot/` | 在 Mac 菜单栏或飞牛 NAS 上管理 aria2 下载 | macOS 版、飞牛 fnOS 版 | Mac 菜单栏展开后的下载队列、飞牛端的任务列表与实时进度 |
| `/inkbuddy/` | 让闲置墨水屏显示 Mac 上正在播放的歌词 | 查看安装指南，进入快速开始 | 阅读器实拍，或明确标为界面预览的实际渲染图 |

AriaPilot 采用一张首页作品卡片和一个官网。首屏的「macOS 版」和「飞牛 fnOS 版」分别跳转到同页的 `#macos` 和 `#fnos`。各区展示对应截图、安装条件、版本发布和文档链接。macOS 区提供应用下载，fnOS 区提供 x86 和 ARM64 的 FPK 选择。两版的版本号和素材从各自仓库核对。

InkBuddy 展示 Mac 运行主程序、墨水屏用浏览器打开局域网地址的过程。首轮主入口引导源码安装，待有适合分发的安装包后可改成下载。

[habu 仓库](https://github.com/mh567/habu) · [AriaPilot macOS 仓库](https://github.com/mh567/AriaPilot) · [AriaPilot fnOS 仓库](https://github.com/mh567/AriaPilot-fnos) · [InkBuddy 仓库](https://github.com/mh567/inkbuddy)

## 内容与路由

- 沿用 `src/content/projects/`，每个对外展示的作品使用一份 Markdown。项目名、简介、仓库和产品地址继续复用现有字段。给需要官网的项目增加可选 `site` 配置，包含稳定的 `slug` 和主操作。作品主色、首屏截图、下载项及文档链接按需填写。多平台作品可配置平台入口与各平台的截图、仓库、下载和安装信息。AriaPilot 的两条首页项目内容整合为一个作品条目。正文使用 Markdown 编辑安装说明和使用场景。
- 使用 `src/pages/[slug].astro` 的 `getStaticPaths()` 在构建时生成已配置的作品页。构建校验 slug 格式、重复及 `admin`、`notes`、`uploads`、`_astro` 等现有路径冲突。作品标题改名时保留 slug，既有分享地址可以继续访问。[Astro 静态路由](https://docs.astro.build/en/guides/routing/#dynamic-routes)
- 已有官网的作品卡片进入域名内页面。其余卡片沿用当前的 `url` 优先、`repo` 次之的规则。habu 的 Demo、Pabu 和博客等已存在的独立站继续使用原地址。短帖、RSS 和后台沿用现行入口。
- 作品页复用站点的基础元信息，设置独立标题、描述和 canonical，有分享图时生成对应的 Open Graph 信息。链接指向作品仓库维护的发行页或文档。可选区块缺少内容时随该区块一起收起导航入口。
- 现有 GitHub Pages 工作流仍发布 `dist/`。新作品随站点部署一起发布，使用已有域名配置。

## 实施与验收

1. 先用 habu 和 AriaPilot 验证一套模板能覆盖在线演示与多平台下载。交付桌面和手机预览，检查首屏、图片阅读、平台锚点和 fnOS 架构选择。
2. 用 InkBuddy 验证源码安装及素材较少时的布局。整理新增作品的字段示例，并验证自建后台编辑、排序项目时保留官网配置。
3. 本地构建验证三个作品路由及其首页卡片链接，确认 AriaPilot 只显示一张卡片，并检查既有外链、短帖、RSS 和后台。用一份新的项目内容验证可直接生成第四个作品页，并检查冲突 slug 的构建错误。发布后逐一打开实际域名路径，确认分享链接、演示、下载或安装入口可达。

实施时从作品仓库或实际运行界面取图，核对所选下载链接和平台要求。首屏拟文案及素材应结合每个作品的现有版本确定。
